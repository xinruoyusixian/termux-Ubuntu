# 05 - 音频

## 方案：Termux 侧 PulseAudio → Android 音频栈
- chroot 直接 ALSA 绕过 AudioFlinger，路由不可靠。可靠链路：
  **chroot(PULSE_SERVER=tcp:127.0.0.1:4713) → Termux pulseaudio(module-aaudio-sink) → Android AAudio/OpenSL**
- chroot 侧装 libpulse0 / pulseaudio-utils / libasound2-plugins。
- 验证：chroot `pactl list short sinks` 看 state:RUNNING；Android `dumpsys audio` 看播放器状态。

## 坑 1：module-sles-sink 在 Android 14+ 上 dlopen 失败
- `cannot locate symbol "Xzs_Construct" referenced by libunwindstack.so` → 改用 **module-aaudio-sink**（pa-user.pa），实测 48000Hz started。

## 坑 2：pulseaudio 不能 --system
- Android 的 `/` 只读拿不到 home → "Daemon startup failed"。必须用户态 `pulseaudio -n -F pa-user.pa`。

## 坑 3：su 调起的音频进程随会话消失
- **现象**：每次重启都没声音，之前能响是手动起的。
- **真因**：`su -c "pulseaudio --daemonize=yes"` 的进程挂在 su 会话下，会话结束被带走；am start-foreground-service 拉音频在这台机器上也没生效。
- **解法**：start-audio.sh 用 **setsid + 前台 pulseaudio**（`--exit-idle-time=-1 --disallow-exit`），脱离会话存活；APK 里内置 start-audio.sh/pa-user.pa 自愈。

## 坑 4：车机 AudioHardening 静音（最隐蔽的坑，v20）
- **现象**：链路自检全绿（sink RUNNING、paplay 成功）但就是没声。
- **证据**：`AF::TrackHandle: OpPlayAudio: track:xxx muted` / `AudioHardening background playback would be muted for com.termux, level: partial`。
- **真因**：PulseAudio 是 su 拉起的 native 进程（PPID=1），ActivityManager 无进程记录 → AudioFlinger 按"前后台"判定 termux 为后台直接静音。`appops PLAY_AUDIO`、`RUN_ANY_IN_BACKGROUND`、deviceidle 白名单全**无效**。
- **解法**：X11 MainActivity 在前台时替整个 uid 持有媒体焦点（AudioFocusRequest AUDIOFOCUS_GAIN, USAGE_MEDIA），onPause 释放。副作用：进桌面会暂停后台音乐（车机单音源可接受）。

## 坑 5：Termux 侧装包不能 root
- Termux apt 拒绝 root 执行；用 RUN_COMMAND 机制以 uid 10183 执行（termux.properties `allow-external-apps=true` + `pm grant com.android.shell ...RUN_COMMAND`）。
- Termux apt 缓存目录被 root 跑坏过 → `chown -R 10183:10183 /data/data/com.termux/cache`。
- **依赖分发**：pulseaudio/proot/libtalloc 无法靠联网装（国内源不稳）→ 打包成 termux-pkgs.bin 随 APK 分发，启动脚本检测缺失自动解包补齐。

## 坑 6：卸载重装后 Termux 无 bootstrap
- usr/bin 里没有 setsid/ps/mkdir/grep → start-audio.sh 的 PATH 必须含 `/system/bin`（用 toybox）。
