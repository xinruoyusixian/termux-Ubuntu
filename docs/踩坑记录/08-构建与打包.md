# 08 - 构建与打包

## 构建链要求
- Gradle 9.2.1 + AGP 8.13.2 + NDK 29.0.14206865 + JDK17 + SDK36。
- **JDK 必须是真 JDK**（含 javac）：D:/carapp-dev/jdk 可用；`Tools/jre` 是 JRE，报 "does not provide the required capabilities: [JAVA_COMPILER]"。
- Gradle 9.2.1 发行版 zip 网络不通时手动放 `~/.gradle/wrapper/dists/gradle-9.2.1-bin/2t0n5ozlw9xmuyvbp7dnzaxug/`（用户迅雷下载）。
- 国内依赖加速：init.gradle 配腾讯云/阿里云镜像。

## 坑 1：APK 内大 asset 的压缩
- `aapt` 会把 .tar.gz 自动解压改名 → asset 命名用 `.bin`。
- `androidResources.noCompress += ["tar.gz","bin"]`，否则 aapt2 去 deflate 1.4G 文件打包巨慢；STORED 后 asset 可直接取 fd。

## 坑 2：Termux bootstrap 机制
- bootstrap 是**构建期**下载 zip → .incbin 编入 libtermux-bootstrap.so → 运行时解压；不是 assets 也不是运行时下载。换 bootstrap 要重编 native。
- `downloadBootstraps` 只留 aarch64；abiFilters 只留 arm64-v8a（省体积省时间）。

## 坑 3：rootfs 打包/解压的属主与权限
- 设备上打包：停桌面 → 清 apt/chrome 缓存 → 卸载挂载点 → 顶层目录列表 tar（排除 /proc /sys /dev /tmp /mnt/sdcard）→ `gzip -1`。gzip 压缩比只有 ~2（大头是 /opt/google/chrome 449M）。
- 解压必须 root + `tar xzpf`（-p 保权限，root 还原 uid）；app 用户 + umask 077 解压会把整盘压成 600/700，sudo/passwd/dbus 全失效。
- 解压后必跑 fix_perms.sh 兜底（toybox tar 对 setuid 恢复不完整）。

## 坑 4：Python tarfile 丢执行位
- 合并 deb 包进 termux-pkgs.bin 时，`usr/bin`、`usr/libexec` 必须强制 mode 755，否则 proot 报"缺少 proot"。

## 坑 5：toybox 兼容
- `find -exec {} +` 不支持 → 改 `xargs -0` 或 `\;`。

## 坑 6：release 包看不到自己的 Log.i
- AGP 默认 proguard `-assumenosideeffects android.util.Log` 删掉 v/d/i → 调试误以为代码没执行。用 debug 包或去掉该规则。

## 坑 7：KernelSU 相关
- KernelSU 3.x 只对**已授权 App** 显示 /system/bin/su；未授权 uid 执行 su 报 "No such file or directory"，**不弹授权框** → App 侧 hasRoot() 检测用 PackageManager 查管理器包名 + 实际 su 可用性，而不是简单 which su。
- 管理器"获取Root失败"红字可能是 A/B 双槽问题：重启换槽后另一槽 boot 没 patch KSU。恢复 = 重刷 patch 过的 boot 到当前槽。
- KernelSU 的 `su 10183 -c` 可用（降权执行）。

## 坑 8：Git Bash 下 adb 的路径转换
- push 目标 `/data/...` 会被 MSYS 转成 Windows 路径。`export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"`，或 heredoc/base64 在设备上写文件。
