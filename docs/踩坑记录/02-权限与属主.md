# 02 - 权限与属主（uid 对齐是整个方案的地基）

## 设计核心：桌面用户 uid = Termux App uid = 10183
- rootfs 内建用户 `alan`，**uid/gid 10183**（= com.termux 的 App uid）。
- 好处一：Android 存储按 uid 判权限 → Termux 有 MANAGE_EXTERNAL_STORAGE 桌面就能读 /mnt/sdcard，不用额外授权。
- 好处二：rootfs 解压/修复可以统一 chown 10183:10183，root(chroot) 与非 root(proot) 两模式都能读写同一份配置。

## 坑 1：共享 log 目录属主卡死非 root 启动
- **现象**：root 模式用过之后切非 root，桌面起不来，App 域报 `sh: can't create .../log/desktop-start.log: Permission denied`。
- **真因**：root 分支的 mountCmd 以 root 身份 `mkdir files/log`，目录变 root:root；非 root（uid 10183）写不进日志，重定向失败导致整个启动脚本没跑。
- **解法**：root 分支 mountCmd 加 `chmod 777 files/log`；已损坏的设备上 `chown -R 10183:10183 files/log`。

## 坑 2：就绪标记 EACCES 中断整个 prepare
- **现象**：解压完成后 App 卡在"未导入"。
- **真因**：`tar xzpf` 以 root 解压把 rootfs 顶层还原成 root:root，App 写不了 `.termux-linux-ready` 标记 → prepare 中断。
- **解法**：就绪判断改成探测 `usr/bin/bash` / `etc/os-release` 存在性；fix_perms 里 `chown 10183:10183 "$R"` 兜底顶层目录。

## 坑 3：.pulse-rt 被 root 跑过 → 普通用户启动 pulseaudio 直接失败
- **现象**：完全无声，`Failed to create secure directory: Unknown error 13`。
- **真因**：曾以 root 起过一次 pulseaudio，`~/.pulse-rt` 变 root:root。
- **解法**：重启音频每次都 `pkill → rm -rf .pulse-rt → mkdir → chown 10183:10183 → 启动`，不猜残留状态。

## 坑 4：/etc/resolv.conf 是 600 的 systemd stub 软链 → Chrome 报 DNS_PROBE
- **真因**：普通用户读不到 DNS 配置。
- **解法**：start-desktop.sh 自动替换为 644 真实文件（nameserver 223.5.5.5 / 119.29.29.29）。

## 坑 5：附加组成员的写法陷阱（glibc initgroups）
- **现象**：写了 `alan:x:10183:media_rw`，alan 仍进不了 media_rw 组（pass_through 目录 0770 media_rw:media_rw 打不开）。
- **真因**：`initgroups(3)` 只扫每个**组条目**的成员字段。用户行第四列的附加组不生效。
- **解法**：必须写 `media_rw:x:1023:alan`（往组里加人，不是往人上加组）。

## 坑 6：/data 是 nosuid → chroot 里 sudo/su/passwd 全失效
- **解法**：`mount -o remount,suid /data`（写进 start-xfce.sh，重启自动）；再配 NOPASSWD sudoers。

## 坑 7：测试污染——用真实 root 跑桌面程序
- **现象**：Chrome 弹"系统无法读取您的偏好设置"。
- **真因**：调试时用 `su` 跑 proot/headless Chrome，往 /home/alan 写了 root 属主文件。
- **解法**：`chown -R 10183:10183 /home/alan`；以后测试别用真 root 跑会写用户目录的程序。

## 坑 8：/run 被打包成 700 alan 属主 → sshd 写 pid 失败；/var/log/btmp 属主错 → sshd 刷警告
- **解法**：start-desktop.sh 每次纠正 `/run`、`/run/sshd`、`/var/log/btmp` 为 root:root。
