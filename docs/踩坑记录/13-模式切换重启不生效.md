# 13 — 模式切换后「立即重启」仍按旧模式启动（v39 / v40 终端会话）

## 现象

终端抽屉点「模式：非ROOT」切到 root（或反向），弹窗点「立即重启」后：

- 标记 `.force-noroot` 已经按预期新建/删除，弹窗文案也正确；
- 但桌面的实际运行模式没变（X server 属主、进程链、日志仍是旧模式）；
- 只有把 App 进程彻底杀掉、冷启动一次才按新模式起来。

## 真因（三条叠加）

### 1. 重启分支用了带缓存的 `hasRoot()`，而不是用户选择的标记

`toggleMode()` 只做一件事：新建/删除 `.force-noroot`。它是模式选择的**唯一真相源**。

旧 `restartDesktop()` 却用 `LinuxLauncher.hasRoot(ctx)` 决定走 root 还是非 root 启动。`hasRoot()` 是**探测结果**：它缓存 su 是否可用，和标记没有必然关系。切换瞬间两者可能不一致 → 按旧模式重启。杀 App 后进程级缓存清空，才恢复一致，所以"杀 App 就好"。

### 2. su 探测有两套独立缓存

同一进程里：

- `isSuAvailable()` 用 `sWorkingSuPath`；
- `hasRoot()` 用 `sSuManagerVerified`。

模式按钮流程里先调 `isSuAvailable()` 写 `sWorkingSuPath`，随后 `restartDesktop()` 调 `hasRoot()` 却可能仍读旧的 `sSuManagerVerified`，一个说能 root、一个说不能。

### 3. 清理与启动用了同一个身份

旧代码把"清理旧桌面"和"启动新桌面"拼成一条命令，整条用 `runSh`（App 身份）或 `runSu`（root 身份）：

- root → 非 root：旧桌面是 root 进程（X server、`su - alan` chroot 链），App 身份**杀不掉**，旧的 root X server 占着 `:0`；
- 非 root → root 若整条用 su：启动脚本以 root 跑，会产生 root 属主污染，非 root 侧以后全 EACCES。

## 解法

### 目标模式只认标记

```java
final boolean targetNonRoot = LinuxLauncher.isNonRootMode();   // .force-noroot
String startCmd = targetNonRoot
        ? "sh " + LinuxLauncher.NOROOT_START_SCRIPT
        : "sh " + START_SCRIPT;
```

`startDesktopStack()` 同样从 `hasRoot()` 改为 `isNonRootMode()`。

### 统一 su 探测缓存

`hasRoot()` 进来先复用 `isSuAvailable()` 已实测通过的路径：

```java
String working = sWorkingSuPath;
if (working != null && verifySuWorks(working)) {
    sSuManagerVerified = Boolean.TRUE;
    return true;
}
```

### 清理与启动身份分离

- **清理**：只要设备有 su，一律用 root 跑 `linux-cleanup.sh`（按命令行通杀 X server / XFCE / proot，并卸载 chroot 挂载；三轮 pkill 防 `xfce4-session` 被 dbus 重新拉起）。
- **启动**：按目标模式选身份——非 root 必须 `runSh`（App uid），root 用 `runSu`。
- 非 root 目标拆成两段：先 `su -c` 跑清理并 `waitFor`，完成后再由 App 身份启动；避免 su 启动造成 root 属主污染。
- **必须等清理真正结束**：`waitFor(120s)` 的返回值要检查，超时强杀 su 进程并放弃启动，退出码非 0（挂载未清零）也取消启动。否则旧 root X server 还占着 `:0`，新 proot 桌面又起不来，等于换了个姿势复现原 bug。
- 整段重启准备放后台线程：`isSuAvailable()` 要实测 su，授权弹窗时可能挂起数秒，放 UI 线程会 ANR。
- 菜单在重启前调用 `ensureRootCleanupScript(ctx)`，因为从非 root 会话切到 root 时磁盘上可能还没有 root 版清理脚本。
- `hasRoot()` 的 v39 分支只采信本次 `verifySuWorks()` 结果，不写回长期缓存 `sSuManagerVerified`，避免 su 授权撤销后陈旧误判。

### 顺带修掉 `.pulse-rt` 属主残留

root 会话里 PulseAudio 若被 root 起过一次，`$FILES/home/.pulse-rt` 变成 `root:root`；切到非 root 后 App uid 写不进去，直接 EACCES（完全无声）。在 `linux-cleanup.sh` 里按 App 数据目录属主删掉重建：

```sh
APP_UID=$(stat -c %u "$FILES" 2>/dev/null)
PULSE_RT="$FILES/home/.pulse-rt"
if [ -n "$APP_UID" ] && [ -e "$PULSE_RT" ]; then
    rm -rf "$PULSE_RT" 2>/dev/null
    mkdir -p "$PULSE_RT" 2>/dev/null
    chown "$APP_UID:$APP_UID" "$PULSE_RT" 2>/dev/null
fi
```

## 验证（v39 真机，Xiaomi Pad 6 Pro / KernelSU）

两个方向都通过真实 UI 点击，且全程没有杀 App：

| 方向 | 标记 | X server 属主 | 桌面进程链 | 启动日志 |
|------|------|---------------|-----------|----------|
| 非 root → root | 删除 | `root termux-x11` | `root su - alan -c … exec startxfce4` → `u0_a167 xfce4-session` | `XFCE(alan) + SSH(2222) … 就绪` |
| root → 非 root | 新建 | `u0_a167 termux-x11` | `u0_a167 proot -0 -r … start-desktop-noroot.sh` → `u0_a167 xfce4-session/xfwm4/xfdesktop/fcitx5` | `桌面(proot) + X + 音频 + 下载目录 就绪` |

切换后 `.pulse-rt` 为 `u0_a167:u0_a167`；`pulseaudio` 正常在 App uid 下运行，AAudio sink 可用，无 EACCES；音频 TCP 4713 监听正常。桌面截图确认图标（浏览器/中英切换/终端/文件管理）与面板齐全，无黑屏。

## v40 补充：终端会话没跟着切（"提示是 root 但终端没变"）

v39 修完桌面栈后，用户又反馈：切到 root、弹窗也提示成功、桌面确实是 root 了，**但终端提示符还是 `$` 和 "Ubuntu(proot) 桌面正在后台启动"**，只有杀 App 冷启动才变。

### 真因

终端里的 shell 会话是 App 冷启动时 `launchLinuxIfNeeded() → prepare() → addNewSessionWithCommand()` 建立的，**和桌面栈是两回事**：

-桌面栈由 `start-xfce*.sh` 启动，v39 的 `restartDesktop()` 重建了它；
-但终端会话（名字以 "Linux" 开头）一直挂在进程里，root 模式是 `chroot ubuntu /bin/bash -l`，非 root 是普通 `sh`。切换模式时只换了桌面，没 kill 旧会话、没重新 `prepare()`，所以终端永远是**冷启动时那个模式**。

### 解法（v40）

模式切换弹窗的"立即重启"从 `PadMenu.restartDesktop()` 改为 `TermuxActivity.restartSystemForModeSwitch()`，四步：

1. 后台清理旧桌面栈（root 全量脚本，等待完成）；
2. UI 线程 kill 所有 "Linux" 会话；
3. 后台按新标记重新 `prepare()`；
4. UI 线程 `addNewSessionWithCommand()` 新建会话（其启动命令自带拉桌面）。

**僵尸会话坑**：kill 会话不能用 `removeTermuxSession()`/`finish()`——SIGKILL 会把 `ExecutionCommand` 置成 failed，`finish()` 在 failed 状态直接 return，会话残留在列表里，下次冷启动 `launchLinuxIfNeeded()` 选中它显示 `[Process completed] (code 137)` 且不再重建。必须照上游 `killAllTermuxExecutionCommands` 的做法：`killIfExecuting(ctx, false)` 后**显式从 `getTermuxSessions()` 列表 remove 对象**。

### 验证（v40 真机，全程未杀 App）

| 方向 | 桌面 | 终端提示符 | launch status |
|------|------|-----------|---------------|
| root → 非 root | proot 栈（u0_a167） | `$` + "Ubuntu(proot) 桌面正在后台启动" | `prepare rooted=false` → `plan=proot` |
| 非 root → root | root 的 `su - alan` chroot 链 | `root@localhost:~#` | `prepare rooted=true` → `plan=chroot` |

两个方向都无 `[Process completed]`；冷启动后切换再切换，会话不残留。

## 铁律

1. **用户选择的模式只有一个真相源**：`.force-noroot`。任何"当前是什么模式"的判断都要问它，不要用带缓存的探测结果代替。
2. **su 探测必须共用一份缓存**；同一个进程里出现两套 su 状态，迟早在切换/重启时咬人。
3. **清理和启动可以不同身份**：清理要能杀掉旧模式的进程（通常 root），启动要用新模式要求的身份（非 root 必须 App uid）。不要把两者拼成一条命令。
4. **跨模式切换要检查运行时目录属主**：`.pulse-rt`、`/tmp` 日志这类目录一旦被 root 创建，非 root 侧就是 EACCES。清理阶段按 App data 目录属主复原。
5. **验证必须走真实 UI**：从 adb/root shell 模拟 App 启动会造成进程属主污染，结论不可信；用 `uiautomator dump` 定位按钮再 `input tap`。
6. **"桌面模式"和"终端会话模式"是两回事**：切换模式必须同时重建桌面栈和终端会话，否则终端永远停在冷启动时的模式。
7. **kill 会话后要显式从列表移除**：SIGKILL 让 ExecutionCommand 变 failed，`finish()` 直接 return；不显式 remove 会留下僵尸会话，下次冷启动显示 `[Process completed]` 且不再重建。
