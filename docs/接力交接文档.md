## 1. 项目是什么

Termux 二次开发的「Ubuntu XFCE 平板版」：**单个 APK** 内置 X11 显示层，点开即用 Ubuntu XFCE 桌面（含 Chrome、输入法、音频）。支持双模式：

- **root 模式**：chroot 进 `files/ubuntu`，完整 root 权限；
- **非 root 模式**：proot，App uid 运行。

## 8. 最痛的坑速查（细节见 docs/踩坑记录/）

1. **`su -c 'sh s.sh "$1"' sh <路径>` 拿到空 `$1`**——Android su 不透传位置参数。必须 `shellQuote()` 单引号转义后拼进命令串。
2. **`/dev/null` 不存在时 `cmd 2>/dev/null` 整条被跳过**——shell 重定向失败直接不执行命令。脚本 stderr 一律 `2>>"$LOG"`。
3. **无 root 恢复 `rm -rf` 会删残 rootfs → 桌面黑屏**——App uid 删不掉 root:root 700 目录，部分失败退出时旧系统已删一半。非 root 一律覆盖式解压，不清空。
4. **bind mount 穿透**：对 `files/ubuntu` 做 `-R` 批量操作/rm 前必须先卸全部 bind mount，否则穿透改坏真实 `/dev/null`（曾致全系统 zygote 崩溃）。
5. **`pkill -f` 自匹配自杀**（踩过三次）：按 pid 文件或 `pgrep -x`。
6. **`tar | gzip` 管道 `$?` 是 gzip 的**：tar 失败被掩盖成"备份成功"。拆两步校验。
7. **备份/恢复执行身份看 `isSuAvailable()`（真实 root 能力），不看 `.force-noroot` 模式标记**——否则生成残缺包还报成功。
8. **桌面运行时 dev tmpfs busy**：普通 umount 失败会触发护栏误拦；用 `umount -l` 多轮复查。`/proc/mounts` 里同一挂载有 `/data/data`、`/data/user/0`、`/data_mirror` 三个别名，卸真实路径后三条一起消失。
9. **`AlertDialog.setItems` 深色主题渲染空白**：自建 View 列表。
10. **su 检测先读流会永久卡死**（授权弹窗时）：先 `waitFor(5s)` 再读流；模式切换检测必须放子线程防 ANR。
11. **root 会话建的文件是 root 属主**：切非 root 后 App uid 写不了 → 启动静默失败。共享目录建完 `chmod 777` 或 chown App uid。
12. **`.mode-initialized` 只初始化一次**：非 root 默认标记只写一次，尊重用户后续切换，别每次启动都覆盖。
13. **KernelSU LKM 重启后丢失**：显示"未安装"属正常特性，需用户手动重载；不要动 boot。
14. **构建**：`-PappVersionName` v37 起生效（此前 build.gradle 只读环境变量）；NDK/tar 相关坑见 08 号文档。
15. **App 域里 `pm path com.termux` 会失败**（Failed transaction 2147483646）：启动脚本拿它当 app_process 的 CLASSPATH → X server 静默死亡（x11.log 0 字节）→ proot 无 X socket → 黑屏。改为 App 启动时写 `.apk-path` 文件，脚本优先读它。
16. **rootfs 的 SELinux MLS 标签不匹配**：root（ksu 域，无类别）解压出的文件是 `app_data_file:s0`，App 是 `untrusted_app:s0:c…`——stat 可以但 readlink/open/exec 全 EACCES，proot 报 `'/bin/bash' not found`（文件明明在）。v38 加 `fix_selinux.sh`：`chcon -R -h` 对齐到 `$FILES_DIR` 标签，幂等；护栏：仍有挂载则中止（防穿透）。探测要用 `readlink(rootfs/bin)`，不能用 `exists()`（后者 access(F_OK) 在标签不匹配时也返回 false，会误判成"rootfs 没导入"）。
17. **`/tmp` 里 root 属主日志挡住 proot 重定向**（铁律 5 的具体发作）：root 会话写 `/tmp/xfce.log` 成 root:root 644，`/tmp` 带 sticky，App uid 既不能覆盖也不能删 → `nohup ... >/tmp/xfce.log` 重定向失败 → **整条命令被跳过** → 桌面四组件一个都不起 = 黑屏。v38 把所有日志改到 `$HOME/.runtime`（App 属主），root 侧启动前先 `chown` 建好空日志。
18. **模式切换后重启仍按旧模式**（v39/v40）：`toggleMode()` 只改 `.force-noroot`，但 `restartDesktop()` 过去用带 su 缓存的 `hasRoot()` 判断模式，且 `isSuAvailable()`/`hasRoot()` 各用一份缓存 → 切换瞬间不一致，只有杀 App 才生效。修法：目标模式**只读标记**；`hasRoot()` 复用 `sWorkingSuPath`；有 su 时用 root 版 `linux-cleanup.sh` 通杀旧桌面（App 身份杀不掉 root 进程），但非 root 目标必须由 App 身份启动（su 启动会造成 root 属主污染）。切换残留的 root 属主 `.pulse-rt` 在清理脚本里按 App data 目录属主重建。**v40 补最后一环**：桌面切了但终端会话没切（终端提示符还是旧模式）——立即重启要 kill 旧 Linux 会话 + 重新 prepare + 新建会话；kill 后必须显式 `getTermuxSessions().remove(ts)`，否则 failed 状态的 finish() 无效、留僵尸会话显示 `[Process completed]`。详见 13 号文档。
