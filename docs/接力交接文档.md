## 1. 项目是什么

Termux 二次开发的「Ubuntu XFCE 平板版」：**单个 APK** 内置 X11 显示层，点开即用 Ubuntu XFCE 桌面（含 Chrome、输入法、音频）。支持双模式：

- **root 模式**：chroot 进 `files/ubuntu`，完整 root 权限；
- **非 root 模式**：proot，App uid 运行。

## 4. 环境与工具约定（重要，照做少踩坑）

- **adb push 用 PowerShell**（Git Bash 会转义 `/sdcard/...` 路径导致 push 到错位置）；**adb shell 执行用 Bash**（PowerShell 不能 spawn `su -c sh ...`）。
- **GitHub 推送**：本机 credential manager 的 token 已失效。PAT 之前从会话记录找回过；新会话找不到时用 GitHub API（blob→tree→commit→ref 四步）绕过 git CONNECT 502，或直接问用户要 token。**不要反复重试 git push**。
- **Release 上传资源名必须 ASCII**（GitHub 接口会把中文名替换成点）。辅助脚本 `tools/upload_asset.py`。
- **解锁平板：直接跑 `bash tools/unlock-pad.sh`**（已真机验证，默认密码 `xw` + 4 个空格；`UNLOCK_PASS` / `UNLOCK_SPACES` / `ADB_BIN` 可覆盖）。脚本自动找 adb、等待屏幕 Awake、按 `wm size` 计算上滑、dump 找 `passwordEntry` 并点击聚焦、输密码、失败重试 3 轮、校验 `mDreamingLockscreen`。**不要再用 screencap 判断界面**（这台设备截图恒黑）。原理与 5 个坑见 `docs/踩坑记录/10-adb与测试技巧.md`。
- **本会话 adb 实际路径**：`/d/carapp-dev/sdk/platform-tools/adb.exe`（PATH 里没有，脚本已内置该路径探测）。
- **设备重启命令不可靠**：`adb reboot`（/dev/pts 缺失时 pty 报错）、`setprop sys.powerctl reboot`（属性服务异常）、`su reboot` 都可能失败。兜底用内核 sysrq：
  ```sh
  echo 1 > /proc/sys/kernel/sysrq; echo b > /proc/sysrq-trigger
  ```

## 5. 接力后第一步 checklist

1. `adb devices` 确认设备在线；不在线则按用户习惯连无线 adb。
2. 检查设备健康：`adb shell ls /dev/null` —— **不存在说明 /dev tmpfs 又丢了**，直接 sysrq 重启（见 §4）。
3. 检查 root：`adb shell su -c id`。失败 = KernelSU 未加载 → 请用户重载，**期间只能测非 root 路径**。
4. `git -C <仓库> log --oneline -3` + GitHub Release 页确认本地与远端一致（应都在 v37 / d31435ab）。
5. 确认 APK 版本：`adb shell dumpsys package com.termux | grep versionName`。
6. 有 root 后：补做 root 模式启动验证（v37 未完成项 §3.1），再排查 proot 黑屏（§3.2）。

## 6. 发布 rootfs SOP（顺序不能乱）

1. 设备上**停桌面**（杀 XFCE / X11 进程，按 pid 文件或 `pgrep -x`，见铁律 2）；
2. 卸载 rootfs 全部运行时挂载（**必须**，护栏会拦）；
3. `tools/clean_rootfs.sh`：删 Chrome profile / 缓存 / `.bash_history` / `recently-used.xbel`；
4. `tools/pack_rootfs_on_device.sh` 打包（内置护栏：仍有挂载则中止；OUT/LOG 路径通用化）；
5. 校验：`gzip -t` 通过 + 解包 grep 个人信息关键字复查；
6. `adb pull` 回本地 `releases/`，用 GitHub API 建 Release 并上传（资源名 ASCII）。

**发布包 vs 用户备份是两条路径**：用户「备份系统」走 `backup-rootfs.sh`，**原样保留个人信息**（用户自己的数据），绝不能拿它当发布包；发布包必须走上面 SOP。

## 8. 最痛的坑速查（细节见 docs/踩坑记录/）

1. **`su -c 'sh s.sh "$1"' sh <路径>` 拿到空 `$1`**——Android su 不透传位置参数。必须 `shellQuote()` 单引号转义后拼进命令串。
2. **`/dev/null` 不存在时 `cmd 2>/dev/null` 整条被跳过**——shell 重定向失败直接不执行命令。脚本 stderr 一律 `2>>"$LOG"`。
3. **无 root 恢复 `rm -rf` 会删残 rootfs → 桌面黑屏**——App uid 删不掉 root:root 700 目录，部分失败退出时旧系统已删一半。非 root 一律覆盖式解压，不清空。
4. **bind mount 穿透**：对 `files/ubuntu` 做 `-R` 批量操作/rm 前必须先卸全部 bind mount，否则穿透改坏真实 `/dev/null`（曾致全系统 zygote 崩溃）。
5. **`pkill -f` 自匹配自杀**（踩过三次）：按 pid 文件或 `pgrep -x`。
6. **`tar | gzip` 管道 `$?` 是 gzip 的**：tar 失败被掩盖成"备份成功"。拆两步校验。
7. **备份/恢复执行身份看 `isSuAvailable()`（真实 root 能力），不看 `.force-noroot` 模式标记**——否则生成残缺包还报成功。
8. **桌面运行时 dev tmpfs busy**：普通 umount 失败会触发护栏误拦；用 `umount -l` 多轮复查。`/proc/mounts` 里同一挂载有 `/data/data`、`/data/user/0`、`/data_mirror` 三个别名，卸真实路径后三条一起消失。
9. **`AlertDialog.setItems` 深色主题渲染空白**：自建 View 列表。
10. **su 检测先读流会永久卡死**（授权弹窗时）：先 `waitFor(5s)` 再读流；模式切换检测必须放子线程防 ANR。
11. **root 会话建的文件是 root 属主**：切非 root 后 App uid 写不了 → 启动静默失败。共享目录建完 `chmod 777` 或 chown App uid。
12. **`.mode-initialized` 只初始化一次**：非 root 默认标记只写一次，尊重用户后续切换，别每次启动都覆盖。
13. **KernelSU LKM 重启后丢失**：显示"未安装"属正常特性，需用户手动重载；不要动 boot。
14. **构建**：`-PappVersionName` v37 起生效（此前 build.gradle 只读环境变量）；NDK/tar 相关坑见 08 号文档。
